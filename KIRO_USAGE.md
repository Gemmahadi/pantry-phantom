## What Kiro is (for this project)

Kiro is AWS's agentic development tool: an IDE, a CLI, a web surface, and Kiro
Crew. Its signature workflow is **spec-driven development**: before code is
written, the agent writes `requirements.md` (user stories + EARS acceptance
criteria), `design.md` (architecture + decisions), and `tasks.md` (trackable
implementation plan) under `.kiro/specs/<feature>/`. Persistent project context
lives in **steering files** (`.kiro/steering/*.md`), and repeatable checks live
in **agent hooks** (`.kiro/hooks/*.json`, v1 schema). The same `.kiro/`
directory works across the IDE, CLI, and Web.

## What was actually done with Kiro

### 1. Kiro CLI installed and verified on Linux — DONE, verified

On 18 Nov 2026, in the build VM (Debian Linux, x86_64):

```bash
curl -fsSL https://cli.kiro.dev/install | bash   # official installer
kiro-cli --version                                # -> kiro-cli 3.4.0
kiro-cli whoami                                   # -> "Not logged in"
kiro-cli --help                                   # lists chat / login / crew / mcp / ...
```

The CLI installs cleanly, runs, and reports its unauthenticated state. The
installer script is kept at `dev/kiro-install.sh` for reference.

### 2. Spec-driven development, in Kiro's format — DONE

The project was planned and built following Kiro's spec workflow, and the
artefacts live in the repo exactly where Kiro puts them:

- `.kiro/specs/pantry-phantom/requirements.md` — 8 requirements, 40+ acceptance
  criteria in EARS notation ("WHEN … THE SYSTEM SHALL …").
- `.kiro/specs/pantry-phantom/design.md` — architecture, data model, matching
  algorithm, decisions (vanilla JS, exact key matching, localStorage privacy).
- `.kiro/specs/pantry-phantom/tasks.md` — the implementation plan, with every
  task checked off and a verification log (including one real bug found during
  verification and fixed: `info.ingredients.length` → `recipe.ingredients.length`).

### 3. Steering files — DONE

`.kiro/steering/product.md` (what the app is, goals, non-goals),
`tech.md` (stack, conventions, commands), `structure.md` (repo layout, naming).
These are the foundation files Kiro generates/uses (`product.md`, `tech.md`,
`structure.md`).

### 4. Agent hooks, v1 schema — DONE (schema verified against official docs)

Two hooks in `.kiro/hooks/`, written to the exact schema published at
<https://kiro.dev/docs/hooks/> (page read 18 Nov 2026):

- `syntax-check-on-save.json` — `PostFileSave`, matcher `\.js$`, runs
  `node --check` on the app's JS files.
- `validate-on-save.json` — `PostFileSave`, matcher `recipes\.js$`, runs
  `node scripts/validate-recipes.js`.

Both hook commands were executed by hand during verification and pass
(`scripts/validate-recipes.js` exits 0). The hook files themselves are valid
JSON in the documented `{"version": "v1", "hooks": [...]}` shape.

### 5. Kiro docs research — DONE

The Kiro CLI install/auth flow, the `.kiro` layout, the spec file trio, the
steering foundation files, and the hooks v1 schema were all checked against
Kiro's official documentation (kiro.dev) and the Kiroween 2026 rules before the
artefacts were written — not copied from memory.

## What was NOT done (blocked, needs the owner)

**The interactive Kiro agent never ran on this project.** That requires signing
in, and authentication needs a browser:

- `kiro-cli login` / `kiro-cli login --use-device-flow` opens a browser OAuth
  flow for AWS Builder ID (free), GitHub, or Google. This build environment has
  no live browser and no signed-in account, and the task instructions forbid
  creating accounts or signing in.
- `kiro-cli whoami` confirms the state: **"Not logged in"**.

So no code in this repo was generated by a live Kiro agent session, and no
Kiro credits were used. The `.kiro/` artefacts were authored by the builder
following Kiro's documented formats, and the hook commands were run manually.
**What unblocks the real thing (5–10 minutes for the owner):** sign in once
with an AWS Builder ID (or GitHub/Google) via `kiro-cli login`, then run
`kiro-cli chat` in the repo — Kiro will pick up the existing specs, steering,
and hooks automatically. The 4,000 free Kiroween credits can be requested on
the Devpost Resources tab by 1 Dec 2026, 12:00 PM PT, after creating the Kiro
account.

The rules require a working application built using Kiro and a repo containing
